# PM 流水线总览与质量门禁

## artifact 依赖关系

```mermaid
flowchart LR
  A[凌乱输入] --> B[01 产品规划书]
  B --> C[02 PRD]
  C --> D[03 交互设计]
  D --> E[04 实现与代码]
```

## 各阶段「完成」定义

### 01 产品规划书

- [ ] 问题陈述与机会假设清晰
- [ ] 用户细分与 Jobs-to-be-Done（或等价框架）
- [ ] 目标与北极星 / 辅助指标
- [ ] 竞品或替代方案对比（可简表）
- [ ] MVP 范围与路线图（至少两档：MVP / V1）
- [ ] 风险、依赖、开放问题清单

### 02 PRD

- [ ] 功能需求带唯一 ID（如 `FR-001`）
- [ ] 每条 FR 有优先级（P0/P1/P2）与验收标准
- [ ] 非功能需求（性能、安全、兼容）若适用
- [ ] 数据实体 / 状态机概要（如适用）
- [ ] 与规划书章节的追溯表

### 03 交互设计

- [ ] 站点地图或 IA 树
- [ ] 核心用户旅程（主路径 + 分支）
- [ ] 页面/组件清单与线框级说明（文字 wireframe 即可）
- [ ] 全局：导航、反馈、加载、空态、错误态
- [ ] 与 FR ID 的映射表

### 04 实现

- [ ] 技术选型说明与目录结构
- [ ] 可本地运行的最小闭环（MVP 主路径）
- [ ] README：安装、启动、环境变量
- [ ] 需求 ID → 文件/模块 映射（简表即可）

## 常见反模式（避免）

| 反模式 | 正确做法 |
|--------|----------|
| PRD 写成散文无 ID | 表格化 + FR 编号 |
| 交互只有漂亮话无页面清单 | 逐页说明字段与操作 |
| 代码与文档脱节 | 提交前对照 FR 勾选 |
| 一次做完全功能 | 标注 MVP，其余进 backlog |

## 文档风格

- 标题层级：`#` 文档名 → `##` 章 → `###` 节
- 表格优于长段落描述枚举
- 决策用「决策记录」小表：背景 / 选项 / 结论 / 理由
